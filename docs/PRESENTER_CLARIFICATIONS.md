Negative marking: the source recommends guessing after eliminating two options and leaving blank if unsure of all four. The deck preserves that advice and clarifies the mathematics. For correctness probability p, expected score is `p − (1−p)/3 = (4p−1)/3`. Uniform guessing among four options has expectation 0; eliminating one gives +1/9 if the remaining three are equally likely; eliminating two gives +1/3. Positive expectation does not guarantee a positive result on an individual question.

Other assumptions: examples 3.1 and 3.3 use the intended successful calls; robust code would check failures and handle interrupted waits. The thread-creation/switching advantages in 2.1 describe typical course-level costs, not universal benchmarks; process creation may use copy-on-write. Diagrams are conceptual teaching models, not C execution. Coverage is a guide, not evidence of a supplied example for every topic. There is no scheduling calculation example in this document. Course Tool 7.1/7.2 and tutorial sheets are recommended by the source; no URLs have been invented.

## Primary references checked

- [WG14 C11 draft N1570](https://www.open-std.org/jtc1/sc22/wg14/www/docs/n1570.pdf), §5.1.2.4 paragraph 25: conflicting actions in different threads, at least one non-atomic, without happens-before ordering constitute a data race; this has undefined behaviour. Paragraph 26 explains the interleaving model for data-race-free programs.
- [POSIX sem_post](https://pubs.opengroup.org/onlinepubs/009695399/functions/sem_post.html): one waiting thread may return from sem_wait; selection follows scheduling policies, with priority and waiting-time rules for specified real-time schedulers.
- [POSIX pthread_join](https://pubs.opengroup.org/onlinepubs/9799919799.2024edition/functions/pthread_join.html): waits until the target thread terminates, unless already terminated.
- [POSIX pthread_mutex_lock](https://pubs.opengroup.org/onlinepubs/009604499/functions/pthread_mutex_lock.html): mutex acquisition and blocking semantics.
- [POSIX write](https://pubs.opengroup.org/onlinepubs/9699919799/functions/write.html): a pipe without an open reader causes EPIPE and SIGPIPE.
- [POSIX signal.h](https://pubs.opengroup.org/onlinepubs/9699919799/basedefs/signal.h.html): SIGPIPE's default action is termination.
- [seL4 FAQ](https://docs.sel4.systems/projects/sel4/frequently-asked-questions) and [IPC tutorial](https://docs.sel4.systems/Tutorials/ipc): minimal kernel mechanisms with services outside the kernel communicating through IPC.
- [POSIX fork](https://pubs.opengroup.org/onlinepubs/9799919799/functions/fork.html) and [wait](https://pubs.opengroup.org/onlinepubs/009696899/functions/wait.html): child/parent fork return values and waiting for child status.
- [POSIX pipe](https://pubs.opengroup.org/onlinepubs/009604599/functions/pipe.html): an open read-end descriptor makes the pipe open for reading.
- [Linux kernel locking guide](https://cdn.kernel.org/doc/html/latest/kernel-hacking/locking.html), “Locks and Uniprocessor Kernels”: implementation depends on SMP and preemption configuration.
- [Linux kernel lock types](https://www.kernel.org/doc/html/latest/locking/locktypes.html): short low-level critical sections and context restrictions make universal mutex advice inaccurate.
